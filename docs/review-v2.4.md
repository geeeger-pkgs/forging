## 一、总评（7.6 / 10）与一句话结论

**总评 7.6 / 10。**

**一句话结论：v2.4 是"代码与语义完成度最高、文档与证据链最松"的一版——两轮设计评审的 5 条 Blocker 在实现层全部真实落地（我用独立复算与 16 例临时内核用例逐条复现通过：三档战力 3.671/5.955/7.805 逐位一致、体力伪码 5 个场景全对、券 5 条契约 + 3 个边界 + 200 次随机试验全对、永久速度无双重计数、离线零耦合、迁移 v11 幂等），门禁 245/18 全绿、体积只 +6.6%；但版本自身的设计文档有 **7 处数字未随 B2 重跑同步**（§3.1「2/5/5」实为 5/5/5、§6「8/25/35」实为 10/26/35、「2.04×/2.26×」实为 2.126×、「2.75%/层」实为 3.10%/层、§9「39 个」为 34、§9「3.93/6.25/8.01」为 3.671/5.955/7.805），一条显式集成点（`sim-audit` 纳排堆叠审计）**没有落地**，且玩法层存在三个结构性薄点：挑战/扫荡零决策、无批量扫荡（每天 12 次起单点）、「前期 6~12 层」目标带对真实前期玩家不可达（T3+10 全套连第 1 层都进不去）。无功能性 Blocker，建议"**当版放行 + 同版补文档/证据**"（M1/M2/M6 合起来约 1 小时，纯文档与截图）。**

评分依据（历史区间 v1.x 8.2~8.9 / v2.0 8.9 / v2.1 初评 7.6 → 修后 8.4~8.5 / v2.2 初评 7.7 → 修后 8.4~8.5 / v2.3 初评 7.7 → 修后 8.4）：
- **明显优于前三版的部分**：**首次出现"零功能性 Blocker"的初评**——前几版初评都至少带 1 条功能性缺陷（v2.1 词缀不可读、v2.2 离线产出 2× 套利、v2.3 离线采矿不进图鉴），本版我把体力/券/双计/迁移/离线五条最容易出语义洞的路径全部用独立脚本打穿，没有找到一条可复现的功能缺陷；门禁与体积纪律延续；数值证据链（JSON + A12 机器校验）仍在位。
- **拉低到 8.0 以下的部分**：1 条显式集成点未落地（sim-audit，属"设计承诺 ≠ 实现"）+ 1 组系统性的文档数字残留（B2 重跑后只更新了 §2/§3.1，§6/§9/§2.2 未同步）+ 3 条玩法/证据结构问题（前期带不可达、零决策 + 无批量、烟测证据不实）。这四类正好是本项目历史测评反复抓的三种缺陷类型（文档数字 ≠ 实现 / 设计目标未达成 / 证据缺口）在本版的变体。

- **现象**：设计 §2.6 #19 与 §6 均写「`sim-audit.mjs` 堆叠审计计入深渊永久速度（+8% 上限：满配 **+304% → +312%**）」，复审也据此判定集成点已补齐；但 `scripts/sim-audit.mjs` **自 v2.1 起未改动**（`git log -- scripts/sim-audit.mjs` 最后一条是 `ae1be32`），全文 grep `abyss|permanent|永久` **零命中**，其 A 段"速度合计（采矿·终局满配）"仍打印 **+2.852（+285.2%）**，与 +304%/+312% 两处都对不上；`+304%` 只作为**硬编码文案**出现在 `scripts/sim-abyss.mjs:359`，没有任何脚本产出该数字。

**M3 · 终局「35 层 / 首通 1,610 / 覆盖 58%」依赖 +8% 永久速度且余量 0.014%（自指 + 脆弱）**

- **现象**：终局画像战力 7.8054 含深渊商店的 8 级永久速度（+0.08）；`req(35) = 7.8043`，**余量 0.0011（0.014%）**。我把永久速度从 0→8 逐级代入：**0~7 级全部只能到 34 层**（7.7254~7.7954），只有恰好买满第 8 级才够 35 层。这意味着：① "终局满配 ≈ 35 层"的锚点把被挑战系统自身的产物当成了输入（自指）；② §2.4/§3.1 的"终局首通 1,610 覆盖 58%"以 35 层为前提，实际玩家在买满 8 级前是 34 层 / 1,530 结晶；③ 任何一项权重或数据微调（甚至四舍五入）都会让"35"翻成"34"。
- **复现**：本报告 §五 复算脚本 "end with N permanent levels" 段（或临时用例 `s.abyss.permanentSpeed = n` 后 `abyssScore` 对比 `abyssRequirement(35)`）。
- **影响**：结论仍在目标带（32~38）内，故不是 Blocker；但"35 层"是 §2.2 定档叙述的中心数字，应把"含永久速度 8 级"写成画像的显式假设，并把余量落进 JSON（如 `builds.end.marginPct`），否则 v3.0 加一条成长轴就会静默翻层。
- **建议**：二选一——① 在 §2.1/§3.1 标注"终局画像含深渊永久速度 8 级（+8%），其在买满前为 34 层"；② 把 base 从 2.764 下调 ~0.5%（≈2.75），让 34 层在无永久速度时也有确定性，同时仍把 35 层留给买满者（顺带重跑 JSON/A12）。

**M4 · 「前期 6~12 层」目标带对真实前期玩家不可达：入门门槛把前期体验推到精通/符文期**

- **现象**：设计的三档画像里，"前期"= 银装 T3 **+10** + **全完美词缀** + **2 枚 T3 最优符文** + **全精通**；我把它逐项拆开复算（同口径）：T3+10 全套**无词缀** = 1.381（**0 层**）；T3+10 + 完美词缀 = 1.961（**0 层**）；再补 T3 符文 = 2.781（1 层）；再补全精通 = 2.851（1 层）；**三者全有**才 = 3.671 → 10 层。也就是说"前期 10 层"实际需要"T3 装备 + 60 点精通（≈总等级 400 量级的 1.5 次满级传承）+ T3 符文 + 全完美词缀"；而一个正常的前期账号（T3+10、无精通无符文）连第 1 层（2.764）都进不去。真实中期侧：T5+10 无词缀 = 3.209（5 层）、T5+5 无词缀 = 2.777（1 层）、T7+10 无词缀 = 4.551（17 层）。
- **复现**：本报告 §五 复算脚本的 "realistic variants" 段（构建输入 = 物品/强化/词缀/符文/精通开关）。
- **影响**：目标带 6~12 在纸面上"命中"，但它描述的不是前期玩家；深渊的实际受众是"装备 T5+ 且精通/符文到位"的中后期账号——这与路线图"v2.4 = 终局：给满配玩家目标"一致，但与 §2.2 的措辞（"前期 10 层"）自相矛盾，而且会让玩家在游戏前几十小时看到"还差 1.4 战力/0 层"的面板而无法参与。
- **建议**：① 或把三档改名（按"装备档 × meta 完成度"命名，如 T3 满配 / T5 满配 / T7 满配）；② 或把 base 下调到让"T3+10 + 完美词缀"（1.961）可打 2~4 层、T3+10+精通（2.85）可打 6~8 层，重新定档并重跑 A12；③ 至少在 §2.2 写明"前期画像含全精通与 T3 符文，纯前期账号预期 0~1 层"。

**M5 · 零决策 + 无批量扫荡：每天 12~48 次单点、挑战恒优且不可能失败**

- **现象**：挑战只在 `战力 ≥ req(bestFloor+1)` 时可用（`abyss.ts:134-141` + UI 禁用 `AbyssPanel.vue:88-95`），成功必然 `bestFloor+1`；扫荡只在挑战不可用时才有意义（35 层首通 80 vs 扫荡 2）。因此玩家的每日动作是"能挑就挑、不能挑就扫"的固定规则，**没有任何取舍**；且系统只提供单次命令（`types.ts:808-810` 三条命令无批量），一次消耗 1 体力。设计 §6 风险表写"扫荡**一键消耗**"，与实现不符（12 体力 = 12 次点击 = 12 条 toast，`store.ts:174-176`）。
- **复现**：面板连点扫荡 12 次；grep 命令联合无 `sweepAbyssMany/all`；`git grep "一键"` 只命中设计文档。
