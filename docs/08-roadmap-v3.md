# Forging v2.0 → v3.0 路线图（自主迭代计划 · 第二阶段）

> 授权：用户自 v2.0 起完全授权继续迭代，直至 v3.0 不再干预
> 迭代流程（每版强制，与 v1.3~v2.0 同标准）：
> **① 创意 → ② 计划（设计文档）→ ③ 评审（独立评审仲裁，Blocker 当版清零）→ ④ 开发 → ⑤ 测试（单测 + 门禁 + 实机烟测）→ ⑥ 资深游戏玩家评审（评分报告）→ ⑦ 提交**
> v3.0 标准：系统纵深 × 内容厚度 × 手感与视听 × 长线目标 四到位，且全部门禁与终验通过

## 二、设计原则（延续 v1.x 已验证的工程规范）

1. **内核纯函数**：一切玩法逻辑落在 `src/game`（无 DOM / 无 Vue / 可单测 / 可序列化），UI 只读 store、只发命令。
2. **命令层唯一入口**：新增交互一律走 `Command` → `applyCommand`，失败返回 `blocked` 事件而非抛错。
3. **内容表驱动**：新增数值一律进 `data/*.json`，由 `scripts/gen-content.mjs` 生成 + `content.ts` 启动校验。
4. **先模拟后定档**：任何涉及数值的新系统，必须先用 `scripts/sim-*.mjs` 出模拟证据，再写进内容表。
5. **存档只增不破**：`SAVE_VERSION` 递增 + 迁移链；旧档加载必须无损，且新增随机性系统迁移时用**确定性**回填（避免旧档被动洗牌）。
6. **离线一致性**：新系统必须明确离线是否结算、是否受增益影响，并写进测试。

## 三、每版硬性门禁

- `npm run typecheck` 零错误（vue-tsc）
- `npm test` 全绿（含新增用例；迁移回归必测）
- `npm run build` 成功，且体积增幅有记录
- **实机烟测**：真实浏览器跑 ≥1 条主路径 + 1 条边界路径，截图落盘 `docs/`
- 测评报告落盘 `docs/review-vX.Y.md`，**Blocker 项当版清零**
- 存档迁移无损（旧版本存档 → 当前版本，逐版回归）

## 四、v3.0 终验清单（预登记）

| 维度 | 验收标准 |
|---|---|
| 架构 | 内核/壳层分离未被破坏；无 TODO/FIXME 债务；依赖仍仅 Vue 运行时 |
| 内容 | 物品/配方/词缀/伙伴/赛季/深渊全表驱动且校验通过；数量级较 v2.0 显著增长 |
| 可玩性 | 至少 8 条并行系统线；短/中/长目标齐备；挂机纯度不降低（离线可推进） |
| 交互与效果 | 全系统键盘可达 + 对比度达标 + 移动端可用；音效与动效覆盖核心反馈 |
| 数值 | 全部关键曲线有模拟证据；无套利/无失控堆叠；新增系统纳入堆叠审计 |
| 稳定性 | 存档 1→N 迁移全链回归；长时结算与边界（队列满/材料不足/离线上限）无异常 |
| 质量 | 测试全绿 / typecheck / build / Lighthouse 四类 ≥95（目标 100） |

## 五、风险与对策（预登记）

| 风险 | 对策 |
|---|---|
| 词缀叠乘导致速度堆叠失控 | 词缀数值走「加法池 + 上限审计」，纳入 `sim-audit` 堆叠段 |
| 新系统膨胀 UI（移动端放不下） | 新面板统一走 NavBar 工具区 + 窄屏折叠；每版复检 ≤900px |
| 存档迁移引入随机回填导致旧档不公平 | 迁移一律确定性（instanceId 哈希种子），并提供「重铸」作为玩家主动刷新手段 |
| 离线结算与新系统冲突 | 新系统默认「离线可结算但排除临时增益」，写入测试 |
| 范围膨胀导致版本拖长 | 每版内容以「可验收的最小完整闭环」为准，超出部分记入下版 backlog |
