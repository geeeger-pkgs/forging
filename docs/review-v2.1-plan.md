## 一、总体结论（有条件通过）

**结论：有条件通过（Conditional Pass）。** 创意方向（词缀=上限、强化=下限；重铸=金币/精华/重铸石的赌局）站得住，内容表与生成器已先行落地，绝大多数集成点正确；但文档存在 **6 条 Blocker**：其中 1 条是重铸核心操作的规则空洞（锁定后池抽取未定义，按当前实现会出现「词缀 id 重复 + 丢失一条词缀」，T7 触发概率 75%），1 条是"配方会把玩家最好的词缀装备当材料吃掉"的存量缺陷被词缀放大，1 条是确定性 roll 可被离线外工具预计算并"垫刀"绕过重铸经济；另有 5 处可复算的事实/数值错误与 §3.1 数值证据空缺。**Blocker 必须清零后才能进入 ⑤ 测试门禁**。

计数：**Blocker 6 条 / Major 8 条 / Minor 7 条**。

### 特别关注项逐条结论

1. **与既有系统的冲突**：命令层唯一入口、事件回流、迁移链三处约定**均未被破坏**（`reforge` 已走 `Command` → `applyCommand`，`enhanceResult.guarded` / `reforged` 走事件回流，`SAVE_VERSION` 8 + `7→8` 迁移已登记）。真正的冲突是**语义层**：①`consumeInputs` 的"消耗最低强化等级实例"规则与词缀资产冲突（B5）；②`recycleGain` 引入了"回收价随装备变化"的新语义，但 `totalValue()`（成就用）仍按固定回收价计算，两者会给出不同的"资产价值"口径（M8）。③`affixSlots` 与既有 `slotsFilled` 成就重复（M6）。
2. **离线结算语义**：确定性 roll **不会**造成离线/在线不一致——在线造装与离线 `grantExpected()` 都走 `addInstance()`（`src/game/settle.ts:171` 与 `:283`），成就/教程奖励发装备同样走该入口（`achievements.ts:82`、`tutorial.ts:66`），同一 `(itemId, instanceId)` 结果恒定；"离线批量造装备刷词缀"在本设计下**不成立**（回档重造也拿不到不同结果，因为 `nextInstanceId` 一并回档）。但**离线期间可被外部工具预计算**：种子只由 `(itemId, instanceId)` 派生且写死在 bundle 里（`src/game/affixes.ts:98-114`），玩家可用存档里的 `nextInstanceId` 反推"下一件装备的词缀"，再用廉价 T1 装备垫刀跳过坏 roll（B6）。重铸本身是真随机且只能在线命令触发，无离线刷取风险。
3. **数值健康**：无正收益套利（开箱 EV 40 > 回收 25；重铸比重新锻造便宜 4.5×~6.7× 且保留强化，重铸是正解）。但**三级造价的第三条腿（精华）不构成约束**：终局 T7 精华产出 ≈ 268/时，而重铸仅 4/次（≈1.5%），"与强化争夺精华"不成立（M3）。真正起作用的门禁是：前中期的金币、终局的**重铸石**（终局产 12.2/时，满锁重铸需 3/次 → 满锁重铸被卡在 ~4 次/时，设计意图成立）。风险点是**流（flow/效率）词缀**：在线效率是"每轮至多 1 次额外产出"的 proc 机制（`settle.ts:98-110`），满配 E=0.8446 → 触发率 0.8655/轮，flow 满配 +9.6% 只换到 +9.1% 触发率；而离线期望用 `(1+eff)` 乘区（含精通），得到 ×2.145 vs 在线 ×1.866（**离线偏乐观 15%**）；且精通/符文的效率在**在线完全不生效**（只算 `aggregateEquipment`）。`sim-audit.mjs:50-62,81` 把效率当乘区得出"×2.394"，口径必须改（M2）。
4. **可玩性**：重铸**有真实决策**（何时开始锁定的阈值策略 + 锁定数 → 造价），且经济上明显优于重新锻造（§五 5.8：T7 镐重造材料 42,676 金 vs 重铸 9,500 金，还保留 +N 的强化投入）。但两处削弱决策厚度：①**T7 词缀条数 = 池大小（4/4）**，组合退化为唯一一种，只剩数值赌博（T5/T6 尚有 4 种组合）（M4）；②T1/T2 条数为 1，"锁定 ≤ n−1"= 不可锁定，UI 现仍显示锁按钮（m3）。
5. **实现可行性**：文档 §2.6 只列了 5 个集成点，实际需要改动 **26+ 处**（§六 逐条 file:line）。其中**未实现且必须做**的：`consumeInputs` 排序规则（B5）、`scripts/sim-affixes.mjs`（B3）、`sim-audit` 口径（M2）、`tests/affixes.test.ts`（§七）、`theme.css` 窄屏弹窗宽度（m2）。文档 §2.8 声明的 `affixes.json` schema 与真实文件**不一致**（B4）。
6. **测试计划（§5）**：A1~A12 覆盖了主路径，**不足以覆盖实现风险**：缺"重铸后词缀 id 不重复"（正是 B1 会漏掉的）、"锁定条在重铸中不参与池抽取"、"离线造装与在线同 roll"、"goldFind 只记一次"、"消耗材料时优先吃低价值实例"、"重铸造价逐档 = 内容表"、"affixSlots 与 slotsFilled 区分"等 10 条关键用例（§七）。
7. **UI/移动端**：右侧栏徽标方案**可行**（10px 字号 + slot 自增高；≤900px 时 `.right` 已改为 `overflow-y: visible` + `auto-fill minmax(150px,1fr)`，反而更宽松）。但"弹窗 ≤900px 全宽"**不能靠现有 dialog 规范实现**：`src/ui/styles/theme.css:89` 的 `.dialog{min-width:380px}` 会压过 `ItemDetailModal.vue:183` 的 `max-width: calc(100vw - 24px)`，在 360px 宽设备上横向溢出 20px（m2）。

### 若只改 5 处数字（最需要修正）

1. `§2.2` 上限列：`lore` 80%→**64%**（8 槽，jewelry 池无 lore）；`fortune` 72%→**68%**；`precision` 8%→**6%**；`aegis` 48%→**44%**；`midas` 36%→**30%**（饰品最高 T5，完美值按 T5 计：6%/9%/3%）。
2. `§3.2` 的"满配 10 槽 T7"→**8 槽 T7 + 2 槽 T5**（`necklace_void`/`ring_void` 不存在，`gen-content.mjs:59-60`）。
3. `§3.3` 的"4 条全 ≥90%"阈值与内容表 `perfectThreshold=0.95` 冲突，必须统一（期望重铸次数差 2 倍：4.5 次 vs 9 次/条）。
4. `§2.3` 备注"一次重铸 ≈ 该档 1/8 小时产出（12.5%）在全档位一致"→ 实测 **4.1%(T2) ~ 12.7%(T7)**，自相矛盾。
5. `§2.4` "从金币档位匀出"→ 实现是从**煤档**匀出（0.20→0.15，`crates.ts:39-48`）。

## 二、Blocker（必须开发前处置）

### B1（最高优先级）重铸锁定规则未定义，按当前实现会「词缀重复 + 丢词缀」
- **章节**：§2.3「锁定：可锁定任意 ≤ n−1 条；锁定条保留原值与品质」；测试 A2/A6。
- **证据**：
  - 实现 `src/game/affixes.ts:84-95` 的 `rollAffixesWith()` 从池中 Fisher-Yates 抽取 n 条（池内不重复），**不排除已锁定的词缀 id**；`src/game/commands.ts:350-353` 再按 `locked.has(i) ? 原值 : 新值` 覆盖。
  - T7 的 `countByTier=4` 恰等于池大小 4，`fresh` 必是**全池的一个排列**；若锁定 index 0 = `keen`，则 `fresh` 中 `keen` 出现在 1..3 号位的概率 = **3/4**，此时结果 = 两条 `keen` + 丢失 `midas`（或其他 id），直接违反 §2.2「条数不变、池不变」与 A2「互不重复」。蒙特卡洛复算（20 万次/档，池 4，锁 1 条）：**n=4 → 75.0%、n=3（T5/T6）→ 50.0%、n=2（T3/T4）→ 25.0%** 出现重复 id。
  - 次生问题：`ItemDetailModal.vue:141` 用 `:key="a.id"` 渲染 v-for，重复 id 会触发 Vue 重复 key 告警并可能渲染错位。
- **修改建议**：在 §2.3 明确"重铸时，**已锁定的词缀 id 从本次抽取池中剔除**，剩余 (n−k) 条从 (池 − 锁定 id) 中不重复抽取"；实现改为 `rollAffixesWith(rng, itemId, excludeIds)`；§5 A6 增加断言"重铸 20 次后，任意一次结果的 id 集合 = 原集合（仅锁定条 id 相同、其余 id 与锁定项互不重复）"，A2 增加"重铸后仍互不重复"。

### B2 `§2.2` 上限表 5 处错误 + `§3.2` 的"10 槽 T7"前提不可达
- **章节**：§2.2 表（第 57-66 行）、§3 第 2 项（第 145 行）。
- **证据**（逐条复算见 §五 5.2）：饰品只有 T1~T5（`scripts/gen-content.mjs:59-60` 的 `maxTier: 5`；`data/items.json` 无 `necklace_void`/`ring_void`；`tests/content.test.ts:31` 断言 `necklace_void` 为 undefined），且 jewelry 池为 `precision/aegis/midas/fortune`（无 `lore`）。因此：
  - `lore`：可出槽 = 3 工具 + 1 武器 + 4 护甲 = **8 槽 → ≤ +64%**（文档写 10 槽 / +80%）。
  - `fortune`：3 工具 + 4 护甲（T7 ×8%）+ 饰品 2 槽（**T5 只有 6%**）= **≤ +68%**（文档写 +72%）。
  - `precision`：2 槽 × T5 3% = **≤ +6%**（文档写 +8%）。
  - `aegis`：4 × 8% + 2 × 6% = **≤ +44%**（文档写 +48%）。
  - `midas`：1 × 12% + 2 × 9% = **≤ +30%**（文档写 +36%）。
  - `keen`/`plenty`/`flow` 三条与文档一致（19.2% / 27.2% / 9.6%）。
- **修改建议**：按上表改写 §2.2 的"可出槽数（上限贡献）"列，并把 §3.2 的输入改为"8 槽 T7 + 2 槽 T5（饰品上限 5 档）"；同时在 §2.2 增一句"饰品仅 5 档，故 jewelry 池词缀的完美值按 T5 计"。

### B3 `§3.1` 数值证据空缺，而 §2 已写入定档数值（违反路线图原则 4「先模拟后定档」）
- **章节**：§3 末尾"结论写入本文档 §3.1（开发前完成，模拟脚本结果）"——**文档中不存在 §3.1**；`scripts/sim-affixes.mjs` 未创建；`sim-audit.mjs` 未更新（grep 无 affix 相关代码）。

### B4 重铸石规格四处互斥（公式 / 内容表 / 代码常量 / 验收标准）
- **章节**：§2.3 公式（`emberstone = 锁定数`）、§2.8 schema（`reforge: { goldBase, goldTierExp, lockFactor, essenceBase, essencePerTier, emberstonePerLock }`）、§7 验收项「商店上架重铸石」、§2.4/§2.6「不设商店直售」。
- **证据**：

### B5 配方输入会静默吃掉玩家最好的词缀装备（存量缺陷被词缀放大）
- **章节**：文档全文未提；§2.6 集成点表缺此项。
- **证据**：`src/game/settle.ts:344-349` 的 `consumeInputs()` 按 `a.enhanceLevel - b.enhanceLevel` **升序**消耗未装备实例；而 T2+ 锻造配方需要 1 件上一档同类装备（`scripts/gen-content.mjs:141`，例：`forge_pick_void` 需要 1 件 `pick_starlite`）。词缀上线后，"高完美度但 +0"的保留件会被优先吃掉，"垃圾但 +5"的反而留下——玩家已投入金/精华/重铸石的资产被静默销毁，且不可撤销（仅 Vite 日志层面无提示）。
- **修改建议**：规则改为"消耗**价值最低**实例"，排序键 `(enhanceLevel, perfectScore)` 升序，并在 §2.6 增加一行集成点 + §5 增加用例（构造 +0 高完美度与 +5 低完美度两件，断言被消耗的是后者）；可选：`describe.ts` 的配方详情中提示"将消耗：T6 镐（+0，完美度 41%）"。

### B6 确定性 roll 可被预计算 + "垫刀"跳过，绕过重铸经济
- **章节**：§2.5、§6 风险表第 5 行（现仅作为"假随机"口碑风险登记）。
- **证据**：`src/game/affixes.ts:98-114` 的种子 = FNV-1a(itemId) ^ ((instanceId + 0x9e3779b9) × 2654435761)，**完全公开在 bundle 内**；`state.nextInstanceId` 又存在存档里。外部工具可在**锻造前**算出下一件目标装备的词缀，用最便宜的 T1 件（铜镐 = 12 铜锭 ≈ 24 铜矿 ≈ 48 金回收价，单轮 6s）垫刀跳过坏 roll：想要"4 条全 ≥90%"平均只需垫 410 件（约 2 万金 + 10 分钟挂机），而重铸路线需 390 万金（§五 5.6）。这使 v2.1 的核心赌局在最优化玩法下失效，"抽奖惊喜"也不成立（产出是确定的，只是玩家看不见）。
- **修改建议**（三选一，必须写入 §2.5 与 §6）：(a) 种子掺入**存档内随机 salt**（迁移 7→8 时生成并持久化，`salt` 不入 bundle）——预计算只能靠读自己的存档，普通玩家无法在游戏内预知；(b) 造装改用真随机 + 造装后立即落盘（`store.ts` 每次 cmd 后 `saveNow()` 已有），接受 SL 风险但记为设计取舍；(c) 保持现状，但把 §6 该行改写为"**可被外部工具预计算与垫刀绕过**"的风险，并在 §5 增加"同 id 结果恒定"以外的对照用例说明这一取舍。推荐 (a)。

## 三、Major

### M1 `§2.3` 备注与自身表格/§6 表述矛盾
- 第 94 行称"让'一次重铸 ≈ 该档 1/8 小时产出'在**全档位保持一致**"，但表内实测占比为 **4.27% / 4.14% / 5.94% / 8.50% / 11.15% / 12.35% / 12.69%**（§五 5.11），T1~T3 相对便宜约 3 倍，"一致"不成立；§6 第 178 行"锁定成本**指数化**"与 §2.3 的加法式 `(1 + 0.9 × 锁定数)` 也不一致。
- 建议：或改文案（"前中期相对便宜、终局≈1/8 小时，鼓励早期多用重铸"），或改数值（T1~T3 上浮到 ~12%），二选一并同步 §6 措辞为"锁定成本线性递增"。

### M2 效率（flow）语义三口径不一致，审计基线必须改
- 证据：在线 proc 只用装备+套装 `aggregateEquipment(...).efficiency`（`src/game/settle.ts:98-110`），**精通与符文的效率不参与**；离线期望用 `agg.efficiency + perk.efficiency`（`settle.ts:127`，符文离线被清空）；`sim-audit.mjs:50-62,81` 又把"装备+符文+精通"当乘区得 `×2.394`。
- 复算：装备+套装 E = 0.8446 → 触发率 `1/(2−E)` = **0.8655/轮**；`flow` 满配 +0.096 → 0.9406 → **0.9439/轮（仅 +9.1%）**；离线口径 `1+eff` = **×2.145** vs 在线 **×1.866（离线偏乐观 15.0%）**。
- 建议：§2.2/§3 统一采用"每轮期望产出倍率 = 1 + f(E)，f(E)=1/(2−E)（E<1），E≥1 时 =1"的口径；`sim-audit` 的效率行改为同口径并删除"×2.394"结论；同时决定"精通/符文的效率是否应参与 proc"（当前是死加成，建议纳入或在文档中说明为仅离线生效）。

### M3 精华不构成有效约束，"三级造价/与强化争夺精华"的辩护不成立
- 复算：终局 T7 精华产出 ≈ **268/时**（950 次奖励结算/时 × 0.11 × (1+2.72)）；满锁重铸仅 **4/次**（≈1.5%），一件装备 +1→+10 共 21 精华 → 每小时可支撑 **12.8 件**。中期 T4/T5 同样是"精华充裕、金币/重铸石为主"。
- 建议：二选一——(a) 提高精华消耗：`essenceByTier = 2×tier`（T7=14）或 `1 + 锁定数`，使"锁得越多越贵"覆盖到精华；(b) 删除 §6 "精华与强化争夺"与"三级造价"的表述，如实写"实际门禁 = 前中期金币 / 终局重铸石"。

### M4 T7 词缀条数 = 池大小 → 组合退化，与 §1「每件都不同」相悖

## 七、测试计划补强建议

§5 的 A1~A12 方向正确，但按上表风险，**至少缺以下 10 条**（建议并入 A 系列，编号顺延）：

- **A13 重铸锁定不破坏池语义（对应 B1）**：T7 武器锁定 0 号（keen）后重铸 20 次，断言：①词缀条数恒为 4；②id 无重复；③锁定条 id/数值不变；④未锁定三条的 id 集合 ⊂ 池 \ 锁定 id。当前实现**必失败**（75% 概率产生重复 id）。
- **A14 锁定数边界与 T1/T2**：T1（1 条）任意锁定都返回 blocked；锁定全部条 → blocked；`locks` 越界/重复/非整数 → blocked 且状态不变（现有实现用 `lockIssue`，补测试固化）。
- **A15 造价逐档 = 内容表**：对 T1~T7 × 锁定 0..3 断言 `reforgeCost().gold === round(goldByTier[tier]×(1+0.9k))`、`essence === essenceByTier[tier]`、`emberstone === k`（并断言不可达组合不会被 UI 提交）。
- **A16 离线确定性一致**：同一 `(itemId, instanceId)` 在 `mode:'expectation'` 的 `grantExpected → addInstance` 与在线 `applyRewards` 得到相同词缀；离线造装不改变随机序列对后续在线结果的影响（固定 rng 双跑对比）。
- **A17 点金只计一次**：`recycleMaterial` / `recycleInstance` / `sweepAutoRecycle` 三路径在同一 `goldFind` 下的收益一致；`openCrate` 金币、任务金币、成就金币**不**受 goldFind 影响（边界）。
- **A18 配方消耗优先级（对应 B5）**：背包中 [+0 完美度 95%] 与 [+5 完美度 40%] 两件同 id 装备，执行需要 1 件的锻造配方后，断言剩下的是高完美度件。
- **A19 词缀与强化解耦**：`aggregateEquipment` 在 +0 与 +10 下词缀贡献相同（A5 的加强版：逐属性断言差值 = 0）；工具 keen 只进本技能、武器 keen 只进 `allSpeed`（已有 A5，建议补"非对称"负例：镐 keen 不影响熔炼）。
- **A20 完美度/阈值一致性**：`perfectScore × 100` 展示值与 UI 口径一致；`perfectThreshold` 只从内容表读取（断言 UI 不再硬编码 0.9，可用源码扫描或把阈值作为 props 的组件测试替代）。
- **A21 迁移回归（加强 A10）**：断言 7→8 后每个 `instance.affixes` 与 `rollAffixes(itemId, instanceId)` 深等；`perfectAffixes` 初值 = 回填中的达标条数（与 §4 文本同步后的口径）；导出/导入往返后词缀不丢；v1→v8 全链后 `nextInstanceId` 与词缀自洽。
- **A22 计数与成就（加强 A11）**：`totalReforges` 每次重铸 +1、失败不计数；`perfectAffixes` 只统计"新摇出"的达标条（造装 + 重铸），锁定条不重复计数；`affixSlots` 与 `slotsFilled` 的差异用例（若按 M6 重定义则补新语义的边界）。
- **A23 内容↔UI 覆盖（新增守护）**：`data/recipes.json` 中 `skill='forging'` 的全部分类都能在 `FORGE_CATEGORIES` 找到页签（该用例在 `src/ui/types.ts` 注释里已被声明，需落地实现，防止"配方不可达"类缺陷复发）。
- **A24 效率口径（对应 M2）**：给定 E=0.8446，断言 100 轮内触发次数 ≈ 86~87（±3），而非 1.0/轮或被 `perk.efficiency` 提高；离线期望与在线期望的偏差断言（写成显式已知差异，或修正后断言一致）。

另建议：把 §五 的 5.2/5.3/5.5/5.6 四张表直接搬进文档 §3.1，并让 `scripts/sim-affixes.mjs` 输出同结构的数字（保证"文档数字 = 脚本输出"可复核）。
