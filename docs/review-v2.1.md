## 一、总评（7.6 / 10）与一句话结论

**总评 7.6 / 10。**

**一句话结论：工程实现（迁移、确定性、测试、体积、移动端）保持了 v2.0 水准，重铸的赌博张力与"完美度"追逐确实成立；但本版的核心新功能在游戏内"读不懂"（9 条词缀的效果没有任何机内说明），且本版作为"数值版"，其唯一的数值证据表 §3.1 有 3 行与模拟脚本不符、2 行没有脚本支撑、1 处门禁结论自相矛盾——补上这两点即可从 7.6 升到 8.5，故建议"先修后放行"。**

评分依据（相对历史区间 8.2~8.9 的定位说明，见 §二）：
- 本版未发现功能性缺陷（无词缀重复、无丢档、无不可达 UI、无套利、无速度触底），工程门禁全绿；
- 但**核心卖点的可读性**与**数值证据的可信度**是"发布前必须补齐"的短板，这是本版低于 8.3 的全部理由；
- 若在放行前完成 B1（词缀效果机内说明，约 30 分钟）与 §3.1 三处数字修正（纯文档），本版应得 **8.4~8.5**（不排除 8.6：重铸锁定策略的经济收益比我预期更扎实）。

## 四、问题清单

### Blocker（必须当版修）

#### B1 词缀效果在游戏内完全不可读（玩家不知道该追什么）

- **现象（可复现）**：打开任意装备弹窗（右侧栏槽位或行囊点击）→ 词缀行只显示「名称 + 数值 + 品质%」，例如 `勘探 +5.0% 84%`，玩家无法知道它作用于什么。9 条词缀中至少 4 条无法从名称推断：庇护（强化失败不降级）、勘探（重铸石掉落）、点金（回收收益）、精准（强化成功率）。
- **证据**：
  - `data/affixes.json` 与 `src/game/types.ts:314-322`（`AffixDef`）**都没有 desc/说明字段**；
  - `src/ui/components/ItemDetailModal.vue:165-167` 只渲染 `affixDef(a.id).name / a.value / 品质`，全模板无 tooltip；
  - 全仓库 grep（`src/`、`data/tutorial.json`）无任何词缀效果文案；效果表只存在于 `docs/design-v2.1.md §2.1`；
  - `ShopPanel.vue:56-64` 只解释"系统"（条数/重铸/重铸石来源），不解释 9 条效果；
  - 唯一的机内提示是事后 toast（`app/store.ts:122` 庇护生效）。
- **影响**：本版卖点是"词缀决定上限、每件装备独一无二"，玩家却无法判断该锁哪条、该为哪条花 9,500 金 + 重铸石；重铸从"有策略的赌博"退化为"数值变大就好"，直接削弱核心循环与决策深度两个维度。新教程也没有任何词缀/重炉引导步。
- **修复建议**：`data/affixes.json` 每条加 `desc`（9 行文案，例：`"庇护：强化失败时有 x% 概率不降级"`），`AffixDef` 补字段，弹窗词缀行加一行 11px 说明（或 `title` 悬浮）；顺带在教程/商店文案里给一句"词缀池按部位不同"。**纯内容+样式改动，无逻辑风险，约 30 分钟**。

### Major（下版必修，登记 backlog）

#### M1 §3.1「逐条锁定 18 次 vs 一次全摇 410 次（便宜约 9.7 倍）」与脚本输出不符

- **证据**：`scripts/sim-affixes.mjs:143-159` 实跑输出「期望重铸次数 ≈ **10.50** 次 / 金 274,579 / 精华 42.0 / 重铸石 20.5」，脚本**根本没有"一次全摇 410 次"这一栏**；我独立复算：一次全摇 P(4 条全 ≥90%) = 0.2222⁴ = 0.2442% → 410 次 × 9,500 = 3,895,594 金，与锁定策略 274,579 金相比是 **14.2×**（不是 9.7×）。`docs/design-v2.1.md:201`（表行）与 `:108`（"便宜约 9.7 倍（§3.1）"）都引用了这组来自设计评审、却与落地脚本不符的数字。
- **影响**：锁定机制的价值被**低估** 46%（9.7× vs 14.2×），且文档自相矛盾（同一张表上一行写 10.5 次、下一行写 18 次）。
- **修复建议**：把该行改为脚本可复现的「10.5 次 / 274.6k 金 vs 410 次 / 389.6 万金 → 便宜 14.2×」，并把"一次全摇"栏补进 `sim-affixes.mjs` 输出，保证"文档数字 = 脚本输出"。

#### M2 §3.1「庇护 −48%（锭 269→140）」不可复现，且脚本无此计算

- **证据**：`grep -n "guard\|庇护\|aegis" scripts/sim-affixes.mjs` → **0 命中**（A~F 六段没有任何庇护测算）。我用 Markov 链精确解 + 60,000 次蒙特卡洛双向验证（成功/降级/庇护判定全部按 `enhance.json` 与 `settle.ts:241-248` 语义）：无庇护 44.0 次尝试 / **209 锭 / 105 精华**；满配 44% 庇护 25.6 次 / **124 锭 / 64 精华** → 实为 **−41% / −40%**，不是 −48%（锭 269→140）。
- **影响**：这是"庇护是否过头"的唯一量化证据，错值会让后续调档（例如把 aegis 上限从 8% 下调到 6%）基于错误基线。
- **修复建议**：把庇护测算写进 `sim-affixes.mjs`（G 段，Markov 或 MC），文档同步为实测值；若要保留 269 口径需给出算式。

#### M3 flow（流畅）的「实际 +15.5%」口径错误，真实产出增益只有 +7.2%

- **证据**：引擎语义是"每轮至多额外产出一份"，每轮期望倍率 = `1 + 1/(2−E)`（`settle.ts:103-115`：`p=E` + 保底 `⌈1/E⌉` 轮，稳态恰好等价 1/(2−E)）。我复算：E=0.8446 → ×1.8655；+flow 0.192（满配）→ E=1.0366 → 保底=1 → ×2.0000。**总产出增益 = 2.0000/1.8655 − 1 = +7.21%**；脚本与文档写的「+15.5%」是**触发率（0.8655→1.0）的相对增幅**（15.54%），不是产出增益。
- **证据行**：`sim-affixes.mjs:126-133`（打印"实际增益 +15.5%"）、`docs/design-v2.1.md:78,198`（"实际 +15.5% … 如实登记，不夸大 ✅"）。
- **影响**：flow 的价值被高估 2.15×，直接影响"词缀相对符文/精通是否过强"的判断（符文 T3+T2 = +65% 效率远比词缀强，若按 15.5% 计会误判）。
- **修复建议**：口径统一为"对总产出的边际增益"，文档写"+19.2% 名义（加法池）→ 在线 +7.2% 实际"，脚本同改；若要保留触发率口径须显式标注"相对触发率"。

#### M4 终局重铸石供给漏算 `prospect`，产量与耗时被低估 46%

- **证据**：`sim-affixes.mjs:240` 用 `(1 + RAREFIND_FULL)` = ×2.84 计算重铸石，**没有叠加 v2.1 自己新增的 `stoneFind`（勘探满配 +110%，design §2.2）**，也没有叠加 keen 满配的 +19.2% 速度。我复算（虚空矿脉 24,000ms、0.7% 掉率）：脚本口径 11.48/h，**v2.1 满配口径 16.72/h（+45.6%）**；"单件完美化 20.5 石 = 1.79h"→ 实为 **1.23h**；`§3.1:202` 的"11.5 个/时 → ≈1.8h"因此偏保守。
- **影响**：把"重铸石 = 长线门禁"的强度夸大了约 1.8 倍（保守方向，不产生破坏，但让 §3.1 的门禁结论失真）。
- **修复建议**：`sim-affixes.mjs` E 段加一列"含勘探/含 keen 的 v2.1 满配"，文档两栏并列（基础口径 vs v2.1 满配口径）。

#### M5「终局门禁是谁」在文档内自相矛盾，且两行用了不同基准

- **证据**：
  - `design §2.3:105`："实际门禁：前中期看金币、**终局看重铸石**"；
  - `design §3.1:200`（单件完美化行）："金 274.6k（=3.7h 产金）… **金为主要门槛**"；
  - `design §3.1:202`（重铸石行）："与金币门槛同量级 ✅"。
  - 按文档自己的基准（74,845 金/时 与 11.48 石/时）：金币 3.67h vs 重铸石 1.79h → **金币紧 2.05 倍**（与 §2.3 相反）；按 v2.1 满配基准（虚空矿脉满配 ≈317k 金/时面值、含点金 30% ≈412k 金/时；16.72 石/时）：金币 0.67h vs 重铸石 1.23h → **重铸石紧 1.8 倍**（与 §2.3 一致）。两行混用基准，谁都对、谁都不成立。
- **影响**：这是"数值健康"维度的核心结论项，评审 M3 专门要求"如实表述门禁归属"，现在等于没定论。
- **修复建议**：选定单一基准（建议 v2.1 满配口径）并把"金币/重铸石"两栏同基准并列，明确写"终局 1 件完美化 ≈ 0.7h 金币 / 1.2h 重铸石 → 重铸石为主线门禁；单次满锁重铸 35,150 金 + 3 石 ≈ 5 分钟收入，不构成节奏阻力"。

#### M6 词缀对"产量/经验/稀有/强化"四条既有曲线的冲击没有模拟证据

- **证据**：`sim-affixes.mjs` B 段只审了**速度**与**效率**；以下四条完全没有出数，而它们的满配上限都进入加法池且永久生效：
  - 经验 `lore` 上限 **+64%** > 整条"智慧精通"线（`data/perks.json` 15×3% = +45%）→ v2.0 发布文档公布的升级时间线（`07-release-v2.0.md §六`，如锻造 Lv50 ≈946h）最多可缩短 ≈31%（×1.45/1.09…按 +109%/ +45% 计 ×0.69）；
  - 产量 `plenty` 上限 **+27.2%**，叠加 flow（proc 上限 ×2.0 结算）后 v2.1 满配吞吐 ≈ **v2.0 满配基线的 ×1.5**（我复算虚空矿脉：v2.0 满配 +285% 速度 ≈211k 金/时面值 → v2.1 满配 ≈317k，含点金 30% ≈412k），v2.0 审计里的"T6/T7 镐回收期 3.2h/5.7h"等结论全部随之移动；
  - 稀有 `fortune` **+68%**（重铸石/精华/小箱同步提速）；
  - 庇护 `aegis` **−41% 强化材料**（见 M2），直接削弱 v2.0 审计中"强化是材料沉淀池"的设计意图。
- **影响**：违反路线图原则 4「先模拟后定档」的精神（速度/效率做了，其余四条没做）；"词缀是否过强/过弱"目前**没有可复核答案**。
- **修复建议**：`sim-affixes.mjs` 增一段"对既有曲线的冲击表"（经验/产量/稀有/强化材料各自 ×倍率 + 对 v2.0 基线的重算），或明确把这四条登记为 v3.0 全量平衡审计的输入并写进 §6 风险表。

#### M7 `prospect` 在 Lv35 前是"死词缀"，且勘探不覆盖小箱来源

- **证据**：重铸石只从 T4+ 矿脉掉落（`data/ores.json`：gold_seam 起，unlockLevel 35）；`prospect` 却在护甲池（T1 起）与饰品池（T1 起）（`data/affixes.json pools`）。T3 护甲 2 条词缀 → 至少含 1 条 `prospect` 的概率 ≈36%，这些词缀在 Lv35 前**数值为 0 收益**；`settle.ts:303-311` 的 `stoneFind` 只作用于 `rareDrops`，工匠小箱的 5% 重铸石（`crates.ts:47-50`）**不受勘探加成**——而 `ShopPanel.vue:62-63` 的文案把"稀有掉落加成"与"工匠小箱"写在同一段，易被读成覆盖小箱。
- **影响**：早期玩家会为一条"暂时完全没用"的词缀付费重铸；中期玩家以为堆勘探能提升开箱产出却发现无效。
- **修复建议**：三选一——①`prospect` 在低档给出等效替代（如 T1~T3 时按"精华掉落 +x%"结算）；②把 `prospect` 从 T1~T3 护甲/饰品池剔除（`gen-content.mjs` 按档生成池，代价是池变小需重新校验组合数）；③至少在弹窗里标注"需 T4 矿脉解锁后生效"。同时把 ShopPanel 文案改为"重铸石来自 T4 以上矿脉掉落（勘探词缀可加成）与小箱（不受加成）"。

## 七、给 v2.2「远征与伙伴」的建议（可执行）

1. **先做"词缀词汇表"，再做伙伴/遗物词条**：把 `desc` 字段、图标、说明进 `affixes.json`（即 B1），并把 v2.2 的"伙伴特质/遗物词条"统一到同一 ID 体系与同一 schema（`effect + base + perTier + desc`）。否则 v2.2 会出现第二套随机词条，玩家要学两遍，且两套词缀的经济价值无法比较（图鉴/赛季也收不了口）。
2. **给重铸一个"解毒剂"作为远征产出**：建议做成"定向重铸券"（重铸时指定一条词缀 id 保底出现）或"品质锁定券"（重铸时保留品质不降），而不是再发一堆重铸石。理由：v2.1 的痛点是"钱/石够也摇不到想要的 id"（T7 锁 3 时最后一条只有 50% 命中），券能精准缓解；而重铸石再增产只会把 M5 的门禁结论进一步推平。
3. **把 `sim-affixes.mjs` 升级为"多基准对比器"并纳入 v2.1 欠账**：一次输出「基础口径 / v2.1 满配口径」两列，自动回答"金币 vs 重铸石谁是门禁"；同时补齐 M6 的四条曲线（经验/产量/稀有/强化材料）与 M2 的庇护段。门禁脚本应成为"文档数字的唯一来源"，本次 3 行不符全部来自人工搬运。
4. **行囊治理与远征产出打包做**：实例级自动回收（按完美度阈值，如"<60% 自动回收"）+ 行囊按完美度排序/筛选 + 一键"同 id 只留最高完美度"。远征会大量产出装备/伙伴，没有这套工具，v2.2 的行囊会比 v2.1 更难用。
5. **给"锁定"补一层非线性，延长决策寿命**：例如按锁定条的**品质**定价（锁 92% 的条比锁 60% 的条贵）、或"锁定越多成功率越低"的第二维惩罚、或提供"重铸到目标自动停"的批量操作。当前策略 10 分钟就被解完（≥90% 即锁、能锁就锁），v2.2 若继续叠加同样是"固定规则可解"的系统，深度会原地踏步。
