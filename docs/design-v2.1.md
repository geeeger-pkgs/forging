## 1. 动机（创意）

v2.0 的问题：**同档装备完全同质**。T7 镐就是 T7 镐，唯一的差别是强化等级（+0~+10）。三个体验缺陷：

1. **锻造缺少惊喜**：玩家锻造第 10 把 T7 剑时没有期待——产出是确定的。
2. **缺长期追逐目标**：强化到 +10 后装备线就"完成"了。
3. **金币/精华后期沉淀**：队列位买满后，金币只剩"回收→无用途"的循环。

v2.1 的创意落点：**给每件装备一次"抽奖身份"，并给它一个可以反复洗的赌桌**。
- 装备产出即带 **词缀（Affix）**：1~4 条，从该类型专属池（各 5 条）中抽取，数值有区间 → 每件都不同，"淘到好货"成为长期乐趣。
- **重铸（Reforge）**：花金币/精华/重铸石重摇词缀，可 **锁定** 满意的词缀（更贵）→ 有策略的赌博循环，同时是金币的第二出口。
- 产出 **完美度** 分数 → 可量化比较、可追逐。

一句话：**强化决定"下限"，词缀决定"上限"。**

## 2. 系统设计（计划）

### 2.1 词缀定义（9 条，4 池 × 5 条）

| id | 名称 | 效果 | 说明 |
|---|---|---|---|
| `keen` | 锋锐 | speed | 速度 +x%（工具=本技能，武器=全技能） |
| `plenty` | 丰产 | quantity | 产量 +x% |
| `flow` | 流畅 | efficiency | 效率 +x% |
| `lore` | 博识 | wisdom | 经验 +x% |
| `fortune` | 幸运 | rareFind | 稀有掉落 +x% |
| `precision` | 精准 | enhanceRate | 强化成功率 +x% |
| `aegis` | 庇护 | guard | **强化失败不降级**概率 +x% |
| `midas` | 点金 | goldFind | **回收收益** +x% |
| `prospect` | 勘探 | stoneFind | **重铸石掉落** +x%（只加权该物品） |

**词缀池（按装备原型 archetype = 物品 category；每池 5 条）**

| 原型 | 槽位 | 池（5 条） | 最高档 |
|---|---|---|---|
| tool | pick / crucible / hammer | keen, plenty, flow, lore, fortune | T7 |
| weapon | mainHand | keen, plenty, flow, lore, midas | T7 |
| armor | head / body / legs / feet | flow, lore, fortune, aegis, prospect | T7 |
| jewelry | necklace / ring | precision, aegis, midas, fortune, prospect | **T5** |

> **池容量 5 > 最大条数 4**（评审 M4）：避免"条数 = 池大小"导致组合退化为唯一解。
> 组合数：T1/T2 = 5 种，T3/T4 = 10 种，T5/T6 = 10 种，T7 = 5 种。
> **饰品只到 T5**（`gen-content.mjs` `maxTier: 5`），故 jewelry 池词缀的完美值按 T5 计——这是上限贡献表的关键前提。

**词缀条数（按档位）**：T1~2 = 1 条，T3~4 = 2 条，T5~6 = 3 条，T7 = 4 条。

### 2.2 数值公式与上限

```
max(tier) = base + perTier × (tier − 1)          // 完美值（roll = 1.0）
value     = max(tier) × roll,  roll ∈ [0.55, 1.0] 均匀
quality   = value / max(tier)                     // 0.55 ~ 1.00
完美度(item) = 平均(quality) × 100%
```

| id | base | perTier | 可出槽分布 | **上限贡献**（满完美） |
|---|---|---|---|---|
| keen | 0.012 | 0.006 | 3×T7 + 1×T7 | +19.2% 速度 |
| plenty | 0.020 | 0.008 | 3×T7 + 1×T7 | +27.2% 产量 |
| flow | 0.006 | 0.003 | 3×T7 + 1×T7 + 4×T7 | +19.2% 效率（名义） |
| lore | 0.020 | 0.010 | 3×T7 + 1×T7 + 4×T7 | +64.0% 经验 |
| fortune | 0.020 | 0.010 | 3×T7 + 4×T7 + 2×T5 | +68.0% 稀有 |
| precision | 0.010 | 0.005 | 2×T5 | +6.0% 强化率 |
| aegis | 0.020 | 0.010 | 4×T7 + 2×T5 | +44.0% 庇护 |
| midas | 0.030 | 0.015 | 1×T7 + 2×T5 | +30.0% 回收金 |
| prospect | 0.050 | 0.025 | 4×T7 + 2×T5 | +110.0% 重铸石率 |

**堆叠纪律**：词缀以**加法**进入既有属性池（与装备基础值、强化、符文、精通同池），不新增乘区；硬上限不因词缀被突破（`minActionTimeMs` 仍是最后防线，见 §3.1）。

**词缀不随强化放大**：强化倍率只作用于装备基础属性，词缀数值恒定 → 强化与词缀是两条独立成长轴（避免乘法耦合失控）。

**效率（flow）的真实价值**（测评 M2/M3）：在线效率是"每轮至多额外产出一份"的 proc（链式上限 1），每轮期望倍率 = `1 + 1/(2−E)`；装备侧 `E=0.8354`（与 `sim-audit.mjs` 同口径）→ `×1.8584`，叠加 `flow` 满配后 `E=1.0274` → `×2.0000`，**对总产出的边际增益仅 +7.6%**（触发率口径 +16.5%，两者不可混用）。离线期望用 `1+E` 乘区（含精通）→ 离线偏乐观（既有取舍，v2.1 未改变，已在审计脚本中如实出数）。

### 2.3 重铸（Reforge）

- **一次重铸**：重摇所有**未锁定**词缀。
- **锁定**：可锁定 ≤ (条数 − 1) 条；锁定条保留原值与品质。
- **池语义（评审 B1）**：重铸时，**已锁定词缀的 id 从本次抽取池中剔除**，剩余条数从「池 − 锁定 id」中不重复抽取 → 保证条数不变、同名词缀永不重复。
- **造价**：

```
gold       = reforgeGold[tier] × (1 + 0.9 × 锁定数)
essence    = essenceByTier[tier]
emberstone = 锁定数 × emberstonePerLock(1)
```

| 档位 | 词缀条数 | 最大锁定 | 无锁 gold | 锁 1 | 锁 2 | 锁 3 | 精华 | 占该档开采金/时 |
|---|---|---|---|---|---|---|---|---|
| T1 | 1 | 0 | 120 | — | — | — | 1 | 4.3% |
| T2 | 1 | 0 | 400 | — | — | — | 2 | 4.1% |
| T3 | 2 | 1 | 1,100 | 2,090 | — | — | 2 | 5.9% |
| T4 | 2 | 1 | 2,600 | 4,940 | — | — | 3 | 8.5% |
| T5 | 3 | 2 | 5,200 | 9,880 | 14,560 | — | 3 | 11.2% |
| T6 | 3 | 2 | 7,600 | 14,440 | 21,280 | — | 4 | 12.4% |
| T7 | 4 | 3 | 9,500 | 18,050 | 26,600 | 35,150 | 4 | 12.7% |

> 「—」= 该档词缀条数不足，无法锁定到该数量（至少留 1 条参与重摇）。
> 造价占该档产金/时 **4.1%(T2) ~ 12.7%(T7)**，单调不跳变：前中期相对便宜（鼓励早期就洗），终局约 1/8 小时/次。
> **门禁归属（统一基准：v2.1 满配口径，测评 M5）**：单件完美化 ≈ 0.7 小时金币（274.6k ÷ 满配金币收入）vs **1.2 小时重铸石**（20.5 ÷ 16.72 个/时）
> → **终局主线门禁 = 重铸石**；单次满锁重铸（35,150 金 + 3 石）≈ 5 分钟收入，不构成节奏阻力。
> 精华产出充裕（终局 ≈268/时 vs 需求 4/次），**不构成约束**——文档如实表述，不再声称"与强化争夺精华"。

- **重铸不影响强化等级**；装备即使在装备中也可重铸（不中断动作，下一轮结算生效）。
- **决策点**：何时开始锁定（品质阈值）+ 锁定几条。逐条锁定比"攒齐一次全摇"便宜 **14.2 倍**（§3.1：274.6k vs 389.6 万金）→ 锁定机制有实质价值。

### 2.4 新资源「重铸石」（emberstone）

| 来源 | 方式 |
|---|---|
| 采矿 T4+ | 稀有掉落（T4 0.2% → T5 0.3% → T6 0.45% → T7 0.7%，随稀有/勘探加成放大） |
| 工匠小箱 | 新增档位（5% 概率 ×1，由**煤档** 20%→15% 匀出，开箱 EV 39.98 仍远高于回收价 25） |
| 成就奖励 | `affix_reforge_200` ×15、`affix_perfect_100` ×20、`affix_count_4` ×5 |

- 回收价 60 金（回收不是正解）。**不设商店直售**：与精华同属"采集侧"资源，保证采矿在后期仍有明确动机。
- `fortune`（通用稀有）与 `prospect`（勘探，仅重铸石）双词缀形成"幸运流/勘探流"配装动机。

### 2.5 产出与迁移

- **新造装备**：`addInstance` 按 (instanceId, itemId, **存档盐**) **确定性** roll 词缀（mulberry32）。
  - 确定性收益：离线/在线一致；读档重造无法改变结果；迁移可无损回填。
  - **盐（评审 B6）**：`meta.affixSalt` 为每档私有随机数，阻断"公开种子表 + 用廉价 T1 件垫刀"的外部预计算（迁移 7→8 时生成并持久化）。
  - **残余风险（已知边界）**：玩家若自行导出存档并实现算法，仍可推算后续 roll 并垫刀；这是"确定性（防读档洗词缀）"与"真随机（防预计算）"之间的取舍，v2.1 选择前者并如实登记。
- **重铸**：使用**真随机**（dispatch 注入 rng）→ 每次重铸结果不同（这是设计上的赌局）。
- **存档 v7 → v8**：旧档装备用同一确定性函数 + 新生成的盐回填词缀（旧档"一夜之间有了词缀"，无损失、可复现、幂等）。

### 2.8 内容与校验

`data/affixes.json`（由 `scripts/gen-content.mjs` 生成）：

```json
{
  "affixes": [{ "id": "keen", "name": "锋锐", "effect": "speed", "base": 0.012, "perTier": 0.006 }, ...],
  "pools": { "tool": [...5], "weapon": [...5], "armor": [...5], "jewelry": [...5] },
  "countByTier": { "1": 1, ..., "7": 4 },
  "rollMin": 0.55, "rollMax": 1.0, "perfectThreshold": 0.95,
  "reforge": {
    "goldByTier": { "1": 120, ..., "7": 9500 },
    "lockGoldFactor": 0.9,
    "essenceByTier": { "1": 1, ..., "7": 4 },
    "emberstonePerLock": 1
  }
}
```

校验项：词缀 id 唯一、effect 合法、数值为正、四池非空且无重复且引用存在、`countByTier` 覆盖全档且 `< 池容量`、roll 区间合法、`perfectThreshold` 落在区间内、逐档金/精华造价存在、`emberstonePerLock ≥ 1`、重铸石物品登记。

**阈值口径（评审 M5）**：`perfectThreshold = 0.95` 用于**成就与 UI 高亮**（"完美词缀"）；§3 模拟中的 **90%** 是玩家追逐的**目标线**，两者语义不同且均已在文档与代码注释中显式声明。
