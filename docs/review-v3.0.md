> 测评人：资深玩家测评代理（放置类游戏 2000+ 小时视角 + 证据优先）｜日期：2026-09-16
> 对象：HEAD `efbfb10`（工作区干净；测评**未修改任何仓库文件**，脚本只在临时副本运行）
> 方法：独立复跑（`vitest` / `typecheck` / `build` / `gen:check` / `audit-fx --check` / 五个 `sim-*.mjs`）+ 独立复算（自写脚本，不引用仓库脚本）+ 逐行代码核对（file:line）

## 一、总评：**6.5 / 10 · 不通过（暂不可作为 3.0 正式版发布）**

**Blocker 1 / Major 7 / Minor 8 / 观察项若干。**

两条历史 Blocker 的**内核部分确实清零**（离线回体不再截断且为时间比例、层词条×连打无越级路径、首通逐层补发、可达层口径唯一 —— 均经独立复算）；证据链三件套可逐字节复现；架构/类型/构建门禁干净。

**但 v3.0 引入了新的玩家可感知缺陷**：深渊面板与内核判定口径不一致（倾钭层会出现"面板置灰、内核能过"），且烟测对此给出了不成立的 ✅；另有行囊「整理」的资产损失风险、连打核心断言为死代码、测试门禁不可复现、位图迁移的中段插入洞、发布文档两处虚假锚点 + 路线图**预填**"8.1 通过"。

## 三、逐条核验（摘要）

- **BL1 离线回体**：内核清零 ✅。但**影响面被文档淡化**：上线间隔 ≥6h 时"每日 2 次上线"同样可打满 48/日（`sim-abyss-output.json.offline.perDay.login2` 原写 24）。
- **BL2 层词条 × 连打**：内核清零 ✅（`challengeAbyss` 恒从 `bestFloor+1` 起逐层判定，传 99 也只截到 3 层，"越级"路径在代码上不存在）。⚠️ 但 `tests/v30.test.ts` 的 F2 成功分支**永不执行**（见 D3）。
- **M1 图鉴分区门槛**：内核 ✅、**UI 半落地**（`codexGate` 未被调用；`CodexPanel` 用线性 pct 判定"可达成"，与分区门槛不一致）、**文档数字错**（实算 83/150/199/222 = 37.4/67.6/89.6/100%，文档写 80/147/199 = 36.0/66.2/89.6%）。
- **M2 内容表/校验**：✅（但 `codexMilestones[].req` 未校验）。
- **M3 `loopBudgetMs`**：**未完全遵守自家预登记**（见下）。
- **M4 赛季 EPOCH 迁移**：代码 ✅（realign 幂等）、**测试缺失**、**窗口未登记**；且"保留 renown"名不副实（`checkSeason` 随即按任务进度重算 → 通常归 0）。
- **M5 L2 离线/在制语义**：内核 ✅（探针复验规则 2 有效）；F5 未覆盖规则 2。
- **M6 DoD**：基本成立但夹带水分（F2 死断言、"四条反套利断言"仅 1 条有测试、"测试全绿"不可复现）。
- **M7 文档矛盾**：旧矛盾已消，新矛盾为里程碑占比与"off 档映射前短路"（实测 `resolveFx` 在 off 判断**之前**执行）。
- **M8 结晶取整**：✅（表/内核/脚本同源）。

**R3 口径修订的判断**：把"p95 相加 ≤0.5ms"改成"p50 合计 ≤0.5 且 max 合计 ≤2ms"，**统计理由成立但确属放宽，且越过了自家预登记的上界**（设计 §2.5 写"新值 ≤0.75ms、须记为降级"；实际允许最坏 2ms）。修复前确实先做了实现削减（matchMedia 缓存把 tick p95 0.70→0.30ms），**不构成发布阻碍**，但应把"放宽"说透并标为降级。

### 复核结论

**处置后通过（可作为 3.0 正式版发布）。**

- Blocker D1 已按最小改动修复并**加了回归用例**（面板口径 == 内核判定，逐层比对 12 层）；
- Major 全部落地：D2 资产保护 + 确认、D3 死代码修复、D4 flaky 消除、D5 指纹覆盖完整序列、D6 补建文件与报告并去掉预填、B-M1 面板接分区门槛 + 数字订正、L2 补 UI 入口；
- 文档层面：赛季窗口、离线影响面、Lighthouse 未达成、R3 降级全部**如实登记**，不再有"声称与实现不符"的表述。

**残余观察项（不阻塞发布，记入 v3.x）**：
1. 连打 ×1/×2/×3 仍是弱支配选择（失败不耗体力 + 逐层补发），"打几层"的取舍强度有限；
2. 前期玩家（T3 全套）进不了第 1 层，面板缺少"需要 T5+/词缀/符文"的获取指引；
3. 实例级回收默认 60% 对高档多词缀装备几乎不触发（其价值主要在低档批量产出）；
4. 位图指纹不符时按持有物重建属**有损**路径（内容表变动版本应写迁移，本条已在使用处注明）；
5. 队首/队尾自动回收与在制消耗件的交互仅覆盖 `craft` 一类输入（当前配方表只有装备类输入，未来扩展需复检）。
