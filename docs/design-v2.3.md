# Forging v2.3 设计文档 ·「图鉴与赛季」（修订版）

> 阶段：① 创意 → ② 计划 → ③ 评审（**初稿被打回**：Blocker 5 / Major 10 / Minor 10，见 `docs/review-v2.3-plan.md`）→ **修订（本文档）** → ④ 开发 → ⑤ 测试 → ⑥ 测评
> 上游：docs/08-roadmap-v3.md（v2.3 = 长线目标：收集与轮换驱动）
> 依赖：v2.2 已发布（徽记/伙伴/遗物，存档 v9）；本版存档 **v10**
> 原则：**先模拟后定档** —— 全部数值取自 `scripts/sim-season.mjs` 输出，并落 `docs/sim-season-output.json` 供测试机器校验（评审建议的"文档数字 = 脚本输出"闭环）。

## 1. 动机（创意）

v2.2 之后游戏有五条并行系统，但缺两样东西：**没有"收集"的终点**（物品/配方/词缀/伙伴/遗物散落各处，看不到完成度）、**没有周期性目标**（日常/周常太短，传承太长）。

v2.3 落点：**给既有内容加一层"目录"，再给中后期玩家一个 14 天的追逐框架**。

一句话：**图鉴回答"我收集了多少"，赛季回答"这两周我在追什么"。**

## 2. 系统设计（计划）

### 2.1 图鉴（Codex）

**6 分区，共 222 条**（脚本清点；口径唯一：`items.json` 的**非遗物**键数）：

| 分区 | 条目 | 发现定义 | 登记点（源头） |
|---|---|---|---|
| 物品（材料/装备/符文） | **104** | 曾持有（材料 > 0 或存在该装备实例） | `state.addMaterial` / `state.addInstance` |
| 配方 | 92 | 曾制作成功 1 次 | `settle.applyRewards`（craft 成功处） |
| 词缀 | 9 | 曾在某件装备上出现 | `state.addInstance`（造装）+ `commands.reforgeInstance` |
| 伙伴 | 6 | 曾招募到 | 由 `state.companions` 推导（不单独存储） |
| 遗物 | 3 | 曾获得 | 由材料表推导（`category === 'relic'`） |
| 矿场 | 8 | 曾开采 1 次 | `settle.applyRewards`（mine 分支） |

> **登记必须在源头（评审 B5）**：材料与装备会被消耗（`consumeInputs` 同窗口先产出后消耗；`sweepAutoRecycle` 会把离线产出直接卖掉），"事后扫描"看不到瞬态；且教学/成就奖励也走 `addInstance`，埋在 `applyRewards` 会漏。
> **次序契约**：`settle(产出/消耗) → checkCodex(里程碑) → sweepAutoRecycle`（否则 `keep:0` 的自动回收玩家所有采集物都不进图鉴）。
> `checkCodexBackfill(state)` 仅用于**冷启动回溯**（老档首次载入跑一次），之后由源头维护。

**持久化**：`meta.codex = { items: string; recipes: string; affixes: string; ores: string }`（**逗号分隔字符串**；测评 M6 实测满图鉴 **3,359 B**（评审 M7 估 3,969B 为 JSON 数组口径）→ 相对新档 2.4KB 增幅约 +140%；v3.0 若需要再评估位图）。

**里程碑（每 25%，达到即自动发奖；**与赛季解耦**，只给自奖励）**

| 里程碑 | 条目 | 金币 | 精华 | 徽记 |
|---|---|---|---|---|
| 25% | 56 | 1,250 | ×10 | — |
| 50% | 111 | 5,000 | ×20 | ×3 |
| 75% | 167 | 11,250 | ×30 | ×3 |
| 100% | 222 | 20,000 | ×40 | ×10 |

> 评审 B3：图鉴**不再给赛季声望** → 不存在"门槛期（总等级 < 60）声望无处安放"的边界，赛季声望只来自赛季任务。

### 2.2 赛季（Season）

**周期与解锁**：14 天（`EPOCH` 常量置于 `data/season.json`）；解锁门槛 **总等级 ≥ 60**（未解锁时不轮换、不计进度）。

**任务**：3 个槽位，从 **6 条模板**按赛季键**确定性**抽取（`pickSeasonTasks(key)`：同一赛季所有玩家一致、可复现；三条互不重复；不复用 `tasks.ts` 的 `rollDailySlot`——它用 `Math.random()`）。赛季槽用**独立结构** `SeasonSlot`（不复用 `TaskSlot`：`tasks.ts:defOf` 只认 daily/weekly，赛季 defId 会返回 undefined）。

**档位与声望**：每档**只计最高达成**（评审 B3-2），不累计。

| 模板 | 铜(10 声望) | 银(20) | 金(40) | 离线可推进 |
|---|---|---|---|---|
| 挖掘 | 4,000 | 9,000 | 18,000 | ✅ |
| 熔炼或锻造 | 1,000 | 2,400 | 4,800 | ✅ |
| 累计金币 | 250,000 | 500,000 | 800,000 | ✅ |
| 完成远征 | 12 | 20 | 28 | ✅（**日历门槛**：2 路线 × 每日 1 次 × 14 天 = 28，按此定档） |
| 强化尝试 | 120 | 320 | 600 | ❌ **纯在线**（离线跳过强化；须标注） |
| 重铸词缀 | 15 | 35 | 60 | ❌ **纯在线**（命令操作；须标注） |

**等级**：1~20 级，每级 **4 声望** → 满级需 **80**（"1 金 + 2 银"；上限 120 留容错）。

**赛季状态硬规则（评审 B3）**

1. **每季清零**：`renown` 与等级随赛季轮换重置为 0；等级奖励因此**每赛季可再领**（属于循环注入，文档按赛季口径表述）。
2. **只计最高档**：每条任务按已达成档位取声望，铜/银/金不叠加。
3. **幂等标记**：`rewardedLevel` 单调不回退；`checkSeason` 即使每 250ms 调用也不会重复发奖。
4. **先结算再轮换**：`checkSeason(now)` 先结算旧赛季的达标与发奖，再执行 `refreshSeason(now)`。
5. **单调守卫**：仅当 `index > stored.index` 才轮换（与 `tasks.ts` 的 `dk > dailyDate` 同型）→ **回拨时钟无效**；前拨**只轮换一次**（与日常一致）。
6. **门槛期**：总等级 < 60 时 `refreshSeason` 不初始化赛季状态、进度不计；解锁后从当前赛季开始。
7. **不保留历史赛季**：轮换即丢弃旧赛季状态（不做赛季档案）。

**离线口径（评审 B2/B4，必须写进 UI 与文档）**：赛季进度由**单调计数器**驱动，离线期间的挖掘/熔炼/锻造/金币/远征计数**照常增长**；**强化与重铸离线零增长**（`offline.ts` 跳过强化、重铸是命令）——这两条模板在 UI 标注「需在线」。

### 2.3 数值定位（§3.1 结论摘要）

- **满级（80 声望 = 1 金 + 2 银）最不利抽取耗时：中期 67h / 终局 74h**，即使按「每日只上线 1 次」（计入口径 8h/日 → 预算 112h）也仅占 **59.4%** 预算 → 不挤占重铸/强化/图鉴等玩法。
- **档位梯度**：全铜最不利 22h（≈0.9 天常驻）→ 休闲玩家也能拿铜档奖励。
- **不构成通胀**（测评 M5 后重定档）：赛季满级 ≈ 66,675 金等价 + 图鉴里程碑 ≈ **131,700** 金等价（100% 档由 22,600 提升到 86,200，与"222 条 + 3 件遗物"的投入相称）= **198,375 金等价 ≈ 终局 2.65 小时产出**；奖励主体是稀缺徽记（赛季 16 + 图鉴 24 = **40/14 天 ≈ 远征产出的 38.1%**）。
- **计入口径假设（必须显式声明）**：预算 = 14 天 × 24h × 折算系数（常驻在线 ×1.0 / 每日 2 次 ×0.667 / 每日 1 次 ×0.333）；速率取 `sim-audit` B 段基线（同档 +5 工具，**不含**符文/精通/词缀）→ 实际玩家更快，结论偏保守。

- `SAVE_VERSION` 9 → **10**：补 `meta.codex = { items:'', recipes:'', affixes:'', ores:'' }` 与 `meta.season = { index: 0, renown: 0, rewardedLevel: 0, tasks: [] }`；`ensureFields` 幂等补齐；载入后跑一次 `checkCodexBackfill`。
