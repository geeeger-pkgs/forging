### Blocker（必须当版修）

#### B1 离线徽记/遗物产出未按成功率加权：低成功率下离线可达在线期望的 2×（离线语义漏洞）

- **现象（可复现）**：同一（伙伴、路线、时长）组合，离线（期望模式）产出的徽记/遗物高于在线长期均值，成功率越低差距越大（公式：`离线/在线 = 2/(1+rate)`，rate→0 时 2×，rate=1/3 时 1.5×，rate=1 时 1×）。金币/材料/重铸石不受影响（它们用了 `yieldShare`）。
- **复现步骤**：
  1. `newGame` 后只保留 `apprentice`（战力 1.0），解锁 `oldmine`（需求 30 → rate=0.0333）；
  2. 离线口径：`rollOutcome(state, oldmine, 8, ['apprentice'], null, 'expectation')` → tokens=0.6000、relics=0.3600；
  3. 在线口径：同参数 `mode='online'` 跑 20,000 次蒙特卡洛 → tokens 均值 **0.3104**、relics 均值 **0.1837**（比值 **1.93× / 1.96×**）；同一对照下 gold 期望 3361.5 vs 在线均值 3368.3（0.998×，口径正确）。
  4. 结果：`advanceExpeditions(..., 'expectation', ...)`（`src/game/offline.ts:50`）结算的 run，其徽记/遗物为"按成功计"而非"按成功率加权"。
- **证据（file:line）**：`src/game/expeditions.ts:171`（期望模式强制 `success=true`）、`:179-181`（`findMul=(1+f.find)*(success?1:0.5)`，而 `tokenExpected/relicExpected` 不再乘 `yieldShare`；对比 `:173` 的 `yieldShare` 与 `:182` 的重铸石已正确加权）。文档 §2.4 规则 4 要求"离线走期望模式"，§2.2 又规定"失败徽记概率减半"——实现只对在线生效。该行在测评期间的两个修复提交中均未被触碰（`git diff d9d67c2..6576b59 -- src/game/expeditions.ts` 仅 +1 行 expected 标记），**在 6576b59 上仍然成立**。
- **影响**：违反本版自己写下的离线纪律（规则 2 的立意即"离线不得优于在线"）。玩家在成功率 <100% 时"卡离线完成"可多拿徽记/遗物（早期近郊 3 次/日 2.0→3.0 枚，+50%），招募/旗帜节奏比设计更快；遗物收集（v2.3 图鉴）同理。金币无影响，故不是经济爆炸，但是可复现的语义错误。
- **修复建议（一行）**：`const findMul = (1 + f.find) * (mode === 'expectation' ? rate + (1 - rate) * 0.5 : success ? 1 : 0.5)`；补一条"期望模式徽记/遗物 = 在线 MC 均值（±2%）"的回归用例。

### Major（登记 backlog / 建议当版顺手修）

#### M1 成长曲线证据含错一档经验："86 次 / 14.3 天"实为"79 次 / 13.1 天"

- **现象**：`sim-expedition.mjs` E 段用 `for (let l = 1; l <= 30; l++) total += xpNeed(l)` 累计到 30 级，把**永远不会被消耗的 `xpForLevel(30)`**（4108）算进总需求；实现侧 `gainCompanionXp` 在 `isMaxLevel(30)` 时即停止扣除（`src/game/expeditions.ts:292-303`），真实总需求 = Σ_{L=1..29} = **47,257**（脚本 51,365）。
- **证据（实测）**：临时用例 R9：`Σ_{1..29}=47257；xpForLevel(30)=4108；Σ_{1..30}=51365`；把伙伴置为 `xp=47257-600` 后领取一次深渊 4h（600 经验）→ **恰好升到 L30**（证明第 30 档经验不参与）。换算：47257/600=78.8 → **79 次 / 13.1 天**（近郊 8h：236 次，非 257 次）。
- **文件**：`scripts/sim-expedition.mjs:153-167`；`docs/design-v2.2.md:119`（§3.1 成长曲线行）、`:163`（§6 风险表）。
- **影响**：这是本版唯一的"长线养成"定量承诺，文档偏保守 8.7%；v3.0 全量审计会继承错值。方向无害，但属于"文档数字 ≠ 实现"的同类问题。
- **修复建议**：脚本循环改 `l < 30`；文档 §3.1/§6 同步为 79 次 / 13.1 天、近郊 236 次；补一条"满级所需经验 = Σ_{1..29}"的断言。

#### M2 "三档净/时完全相同"不成立：补给 ceil 取整使 1h 档最高亏 3.3%，且 1h 档突破 ≤5% 补给护栏

  - 古代遗迹有勤勉：1h 1 个 → 2628.1 vs 8h 6 个 → 2659.3（低 1.17%）；
  - 近郊/矿道无勤勉因数量恰为整数而齐平；矿道有勤勉 1h 1607.4 vs 8h 1609.9。
  - **1h 档补给占毛产出**：深渊无勤勉 490/6736.1 = **7.27% > 5%**（8h 档 4.09%）；矿道 1h 4.80%。

#### M3 旗帜战力乘区口径写反：文档/脚本用加法 1.24，实现是乘算 1.2597（天花板 470.2 vs 477.68）

- **现象**：`docs/design-v2.2.md:33` 写"每级 +8%（**乘算**，满级 **×1.24**）"——"乘算"应为 1.08³=1.2597；实现与测试都用乘算（`src/game/expeditions.ts:50-52`；`src/game/content.ts:262`；`tests/expedition.test.ts:56-57` 断言 1.259712），而 `sim-expedition.mjs:107-110` 用 `1+0.08×3=1.24` 得天花板 470.2；实际天花板 **477.68**。

#### M4 "编队"不是真实决策（评审 M4 的处置目标未达成）；特质存在被支配项

- **现象**：
  1. 同一伙伴可**同时**出现在 4 条路线的 run 中（仓库自己的用例就这么用：`tests/expedition.test.ts:422-435` 用同一 `apprentice` 同派近郊+矿道），内核没有任何"伙伴占用"校验（`commands.ts:431-459` 只查归属与上限）；
